# 面试作品集说明

这个项目适合展示“桌面应用 + 云模型服务 + 持久化检索 + 嵌入式控制”的完整工程链路。项目起源于你与朋友共同开发的 Emobot；原仓库在朋友的 GitHub，进一步继承了 Desk-Emoji。GPLv3 和动画来源在 NOTICE 中保留。新代码由本次重写形成，并使用 AI 辅助；不要把工具协助、朋友的工作或保留素材说成自己独立完成。

## 建议展示路径

1. 运行 `emobot --demo gui`，说明无硬件时也能检查交互、动作和数据流，但演示提供器不代表模型智能表现。
2. 切换中文/英文、编辑人格；展示 59 个动作入口和模拟动作输出。
3. 导入硬件文档，问“如何烧录固件”，解释关键词检索与可选向量检索、命中文档后模型路由。
4. 增加一条偏好、编辑、删除，解释来源核对、旧向量失效及删除后的聊天清理。
5. 连接自己的实物，演示小角度舵机、表情、手势和一轮独立语音；这一步需要先完成 HARDWARE 中的 bring-up 清单。
6. 打开四轮审查记录，展示“测试先暴露问题 → 修复 → 回归通过”，说明 Python 3.13 适配和已测与未测的边界。

## 可以解释的工程决策

- GUI 与设备/API I/O 分离：所有 Tk 控件由主线程操作，单一后台任务通过队列返回进度，防止跨线程控件错误。
- 模型输出是输入数据：解析 JSON 并核对动作名字、数量、时长；设备再次验证，避免模型直接控制任意命令。
- 默认 SQLite：面试演示不需要先搭数据库；PostgreSQL/pgvector是同一持久化接口的可选配置。
- 关键词降级：embedding 服务不可用仍能搜索文档，失败不会变成“没有记忆”的假结论。
- 保守记忆：明确长期偏好才候选，事实必须来自当前用户语句；编辑后不能继续用旧向量，删除需要清理重复信息来源。
- 固件的固定缓冲录音与流式文件编码：降低 WAV/base64 全量内存分配，声云请求在独立任务进行，USB/BLE 控制保持可用。
- 动画压缩：保留既有美术素材，转换存储格式并核对逐帧数据；这属于资源压缩与渲染改造，不是重新创作动画。
